## 1. 판정 윈도우 — 후킹 없이 바꿀 수 있습니다

> **초판 정정.** "판정 엔진 조작은 어려움 (`LogicalNotePlayer` 멤버 100% 난독화)"라고 적었는데
> **틀렸습니다.** 난독화된 건 맞지만, 정작 바꾸고 싶은 값이 **쓰기 가능한 `public static double`**
> 로 노출돼 있습니다. Harmony 후킹이 전혀 필요 없습니다.

```csharp
// 전부 ms 단위. 값을 키우면 그만큼 판정이 후해진다.
LogicalNotePlayer._re = 200;   // Shiny  (원래 25)
LogicalNotePlayer._Re = 200;   // Perfect(원래 50)
```

디컴파일로 확인한 접근자:

```csharp
public unsafe static double _re
{
    get { IL2CPP.il2cpp_field_static_get_value(NativeFieldInfoPtr__re, &result); ... }
    set { IL2CPP.il2cpp_field_static_set_value(NativeFieldInfoPtr__re, &num); }   // ← setter 살아 있음
}
```

### 실측 기본값 (2026-09-10)

| 필드 | 기본값(ms) | 대응 판정 |
|---|---:|---|
| `_re` | 25 | Shiny |
| `_Re` | 50 | Perfect (Early/Late) |
| `_se` | 100 | Near (Early/Late) |
| `_Se` | 150 | 판정 컷오프 / Miss 경계 |
| `_te` | 50 | 두 번째 완화 래더 |
| `_Te` | 100 | 〃 |
| `_ue` | 200 | 〃 |

일곱 개 **전부 static** 입니다. 덤프 스텁은 `static` 수식어를 잃어버리므로 스텁만 보면
인스턴스 필드처럼 보입니다 — [04번 문서](04-후킹-함정과-성능.md) 참고.

등급 구성은 `JudgementTypeCount` 와 정확히 맞물립니다:

```csharp
// Il2Cppifapp.Game.Data.JudgementTypeCount (필드명 무손상)
public struct JudgementTypeCount {
    public UInt16 None, Miss, NearEarly, NearLate, PerfectEarly, PerfectLate, Shiny;
}
```

화면 표기는 `GameScene` 프리팹 필드 기준으로 `exactPlusTextPrefab`(Shiny) / `exactTextPrefab` /
`nearTextPrefab` / `missTextPrefab` — Arcaea의 Pure/Far/Lost 계보 그대로입니다.

**미확정:** 래더가 두 벌(`_re~_Se` 와 `_te~_ue`)인 이유는 아직 모릅니다. 노트 종류별(홀드·플릭·스카이)
이거나 릴리즈 판정용으로 보입니다. 한쪽만 바꿔보고 인게임 표기가 어떻게 변하는지로 갈라내는 것이
가장 빠릅니다.

**주의:** static 필드라 씬 로드마다 초기화될 수 있습니다. 한 번만 쓰지 말고 곡 진입 시점에
다시 써주는 편이 안전합니다.

### 판정 관련 그 밖의 구조

```csharp
// Il2Cpp_K._cH — 판정 이벤트/윈도우 (생성자 파라미터 이름 살아 있음)
public _cH(long id, double timestampMs, double absoluteTimestampMs, _CH type);
```

`_T._XC : Dictionary<long, Memory<_cH>>` 가 **노트 id → 판정 윈도우** 매핑입니다.
`_cH` 에는 좌표가 없고 시간·id·타입만 있습니다 — 판정의 **위치** 성분은
`_fA._He`/`_ie` 쪽입니다([02번 문서](02-런타임-차트-주입.md)).

입력 쪽 진입점으로 보이는 메서드:

```csharp
public void _hb(double, double, double, Dictionary<_CA, UnorderedListVal<int>>, double = 0);
```

`Dictionary<_CA, UnorderedListVal<int>>` = **side별 int 목록** — 눌린 레인 인덱스로 추정됩니다.
이것이 `_fA._He`/`_ie`(노트의 판정 레인)와 대조되는 구조로 보입니다. 미검증.

### 더 쉬운 우회로

게임에 **`AssistMode` 가 내장**되어 있습니다 (`GeneralSaveStateV5.AssistMode`,
`AssistModePlayerContainer`, `AssistModeModal`). 판정 자체가 아니라 보조 기능이 필요하면 이쪽이 맞습니다.

## 2. 시간·오디오 — `_jiA` 말고 `_miA`

곡이 흐르는 동안 0.6초 간격으로 샘플링해 갈라낸 결과입니다.

| 대상 | 관측 | 정체 |
|---|---|---|
| `LogicalNotePlayer._xe` `_Xe` `_a` `_A` | 곡 내내 `133499.571` 고정 (Δ=0) | **차트 종료 시각(ms) 상수** |
| `_Dg._jiA()` | 곡 내내 `135.669` 고정 | **재생 위치가 아니다.** 전체 길이 계열 |
| `_Dg._miA()` | `-2.521 → -1.920 → … → -0.121 → 0.288 → …` | **재생 위치(초). 리드인 동안 음수** |

`_miA` 가 0을 지나는 순간이 음악 시작점입니다. 리듬게임의 전형적인 음수 리드인 클럭이라,
차트 타이밍을 다룰 때 기준 시계로 쓸 값은 이쪽입니다.

### `_xe` 는 마지막 노트의 종료 시각이다

결정적인 증거는 노트 덤프의 마지막 줄입니다:

```
노트 #131  Sky  judgeStart 133071  judgeEnd 133500     ← 차트 마지막 노트
_xe = _Xe = _a = _A = 133499.571…                      ← 반올림 전 실제값
```

관계식도 맞아떨어집니다: `_jiA`(135.669초) ≈ `_xe`/1000(133.500초) + 리드인(≈2.17초).

즉 `_xe` 계열은 **노트 리스트에서 파생되는 값**이므로, 커스텀 차트로 노트를 바꾸면
**같이 갱신해야** 재생바 길이와 곡 종료 판정이 맞습니다.

**미확정:** `_VUA`(오디오 핸들 길이)는 48kHz PCM 샘플로 환산하면 26.7초가 나오는데
같은 곡 차트 길이가 133.5초라 앞뒤가 안 맞습니다. 단위 미상이므로 환산값을 신뢰하지 말 것.

`StreamingAssetsMapping.FileLength` 검증 때문에 **크기를 맞춰야** 합니다.

## 3. 세이브 데이터

```
C:\Users\<user>\AppData\LocalLow\lowiro\infalsus\<SteamID64>\release\savestate_V3.sav
```

**암호화·압축 없음.** 194KB, 엔트로피 2.148 bits/byte, 0x00 비율 72.5% — 생 MemoryPack 바이트입니다.
Steam Cloud 동기화(`steam_autocloud.vdf`) 대상이니 편집 시 클라우드 충돌만 주의하면 됩니다.

루트 구조 (`SingleFileSaveDataV2`, 멤버 9개 — 파일 첫 바이트 `0x09` 와 일치):

```csharp
CardInventory      CardInventory
IotaInventory      IotaInventory
GameResultsV4      GameResults
EncounterResults   EncounterResults
StoryStateV5       StoryToState
GeneralSaveStateV5 GeneralSaveState
RecipeSaveStateV2  RecipeSaveState
LootDropState      LootDropState
GrantsSaveState    GrantsSaveState
```

`GeneralSaveStateV5` 에 `AssistMode`, `TutorialFlags`, `StoryChoiceToResult`, `SeenSongVideoIds`,
마지막 선택 곡/난이도 등이 전부 평문 필드로 들어 있습니다.

카드 구조체 `CardInstance` 도 완전 무손상:

```csharp
public int CardId, CardBaseId;
public byte TierIndex, IsSR;
public CardColorType CardColorType;   // Colorless/Red/Yellow/Green/Blue/Purple
public double BasePower, BaseFortitude;
public short TraitSlotType1..3, TraitId1..3;
```

편집은 `MemoryPack` NuGet + `SingleFileSaveDataV2` 미러 클래스로 왕복 가능합니다.

키 설정은 별도 평문 파일 `userV2.prefs` (`k "keybind_BottomLane0" / v 51` 형식).

- 평문 DSL 텍스트 472개. `Game.NovelEngine.*` 난독화 **0%** (1,218 멤버 전부 원본 이름)

- 밸런스 데이터도 평문 — `EncounterDetail` 에 `FarChance`, `MissChance`, `DifficultyRating`,

### 빨리감기 잠금 해제 (동작 확인됨)

스킵은 원래 스크립트가 `StoryFastForwardAllowCommand`(문법상 `AllowFastForward`)를 실행한
구간에서만 켜집니다. 그 결과가 `StoryState.IsStoryAllowFastForward` 이고, false면 메뉴의
빨리감기 버튼이 비활성으로 보입니다.

```csharp
StoryScene._gS.IsStoryAllowFastForward = true;   // 주기적으로 눌러주면 항상 켜짐
```

`_gS` 는 난독화된 이름이라 업데이트 시 바뀔 수 있습니다. 그때는
`Decompiled/Il2Cppifapp/Game/Scenes/StoryScene.cs` 에서 `public StoryState _xx { get; set; }` 를
다시 찾을 것.
