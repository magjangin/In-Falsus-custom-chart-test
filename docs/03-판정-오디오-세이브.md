## 1. 판정 윈도우 — 후킹 없이 바꿀 수 있습니다

> **초판 정정.** "판정 엔진 조작은 어려움 (`LogicalNotePlayer` 멤버 100% 난독화)"라고 적었는데
> **틀렸습니다.** 난독화된 건 맞지만, 정작 바꾸고 싶은 값이 **쓰기 가능한 `public static double`**
> 로 노출돼 있습니다. Harmony 후킹이 전혀 필요 없습니다.

```csharp
// 전부 ms 단위. 값을 키우면 그만큼 판정이 후해진다.
LogicalNotePlayer._re = 200;   // Shiny  (원래 25)
LogicalNotePlayer._Re = 200;   // Perfect(원래 50)
```

디컴파일로 확인한 접근자:

```csharp
public unsafe static double _re
{
    get { IL2CPP.il2cpp_field_static_get_value(NativeFieldInfoPtr__re, &result); ... }
    set { IL2CPP.il2cpp_field_static_set_value(NativeFieldInfoPtr__re, &num); }   // ← setter 살아 있음
}
```

### 실측 기본값 (2026-09-10)

| 필드 | 기본값(ms) | 대응 판정 |
|---|---:|---|
| `_re` | 25 | Shiny |
| `_Re` | 50 | Perfect (Early/Late) |
| `_se` | 100 | Near (Early/Late) |
| `_Se` | 150 | 판정 컷오프 / Miss 경계 |
| `_te` | 50 | 두 번째 완화 래더 |
| `_Te` | 100 | 〃 |
| `_ue` | 200 | 〃 |

일곱 개 **전부 static** 입니다. 덤프 스텁은 `static` 수식어를 잃어버리므로 스텁만 보면
인스턴스 필드처럼 보입니다 — [04번 문서](04-후킹-함정과-성능.md) 참고.

등급 구성은 `JudgementTypeCount` 와 정확히 맞물립니다:

```csharp
// Il2Cppifapp.Game.Data.JudgementTypeCount (필드명 무손상)
public struct JudgementTypeCount {
    public UInt16 None, Miss, NearEarly, NearLate, PerfectEarly, PerfectLate, Shiny;
}
```

화면 표기는 `GameScene` 프리팹 필드 기준으로 `exactPlusTextPrefab`(Shiny) / `exactTextPrefab` /
`nearTextPrefab` / `missTextPrefab` — Arcaea의 Pure/Far/Lost 계보 그대로입니다.

**미확정:** 래더가 두 벌(`_re~_Se` 와 `_te~_ue`)인 이유는 아직 모릅니다. 노트 종류별(홀드·플릭·스카이)
이거나 릴리즈 판정용으로 보입니다. 한쪽만 바꿔보고 인게임 표기가 어떻게 변하는지로 갈라내는 것이
가장 빠릅니다.

**주의:** static 필드라 씬 로드마다 초기화될 수 있습니다. 한 번만 쓰지 말고 곡 진입 시점에
다시 써주는 편이 안전합니다.

### 판정 관련 그 밖의 구조

```csharp
// Il2Cpp_K._cH — 판정 이벤트/윈도우 (생성자 파라미터 이름 살아 있음)
public _cH(long id, double timestampMs, double absoluteTimestampMs, _CH type);
```

`_T._XC : Dictionary<long, Memory<_cH>>` 가 **노트 id → 판정 윈도우** 매핑입니다.
`_cH` 에는 좌표가 없고 시간·id·타입만 있습니다 — 판정의 **위치** 성분은
`_fA._He`/`_ie` 쪽입니다([02번 문서](02-런타임-차트-주입.md)).

입력 쪽 진입점으로 보이는 메서드:

```csharp
public void _hb(double, double, double, Dictionary<_CA, UnorderedListVal<int>>, double = 0);
```

`Dictionary<_CA, UnorderedListVal<int>>` = **side별 int 목록** — 눌린 레인 인덱스로 추정됩니다.
이것이 `_fA._He`/`_ie`(노트의 판정 레인)와 대조되는 구조로 보입니다. 미검증.

### 더 쉬운 우회로

게임에 **`AssistMode` 가 내장**되어 있습니다 (`GeneralSaveStateV5.AssistMode`,
`AssistModePlayerContainer`, `AssistModeModal`). 판정 자체가 아니라 보조 기능이 필요하면 이쪽이 맞습니다.

## 2. 시간·오디오 — `_jiA` 말고 `_miA`

곡이 흐르는 동안 0.6초 간격으로 샘플링해 갈라낸 결과입니다.

| 대상 | 관측 | 정체 |
|---|---|---|
| `LogicalNotePlayer._xe` `_Xe` `_a` `_A` | 곡 내내 `133499.571` 고정 (Δ=0) | **차트 종료 시각(ms) 상수** |
| `_Dg._jiA()` | 곡 내내 `135.669` 고정 | **재생 위치가 아니다.** 전체 길이 계열 |
| `_Dg._miA()` | `-2.521 → -1.920 → … → -0.121 → 0.288 → …` | **재생 위치(초). 리드인 동안 음수** |

`_miA` 가 0을 지나는 순간이 음악 시작점입니다. 리듬게임의 전형적인 음수 리드인 클럭이라,
차트 타이밍을 다룰 때 기준 시계로 쓸 값은 이쪽입니다.

### `_xe` 는 마지막 노트의 종료 시각이다

결정적인 증거는 노트 덤프의 마지막 줄입니다:

```
노트 #131  Sky  judgeStart 133071  judgeEnd 133500     ← 차트 마지막 노트
_xe = _Xe = _a = _A = 133499.571…                      ← 반올림 전 실제값
```

관계식도 맞아떨어집니다: `_jiA`(135.669초) ≈ `_xe`/1000(133.500초) + 리드인(≈2.17초).

즉 `_xe` 계열은 **노트 리스트에서 파생되는 값**이므로, 커스텀 차트로 노트를 바꾸면
**같이 갱신해야** 재생바 길이와 곡 종료 판정이 맞습니다.

### `_VUA` 는 길이가 아니다

같은 곡(`alamode.wav`, AssetId 5610)인데 실행할 때마다 값이 달랐습니다:

```
1,058,398 / 1,283,263 / 1,305,864 / 1,349,736 / 1,471,360 / 1,530,184   (2026-09-09 ~ 09-14 로그)
0                                                                   (2026-09-23, 핸들 생성 직후 폴링)
```

길이라면 값이 고정이어야 합니다. 핸들이 생긴 직후엔 0이고 찍는 시점마다 달라지므로
**로드·디코드 진행 카운터 계열**로 보입니다. `BgmHook` 로그의 "오디오 스트림 크기: N 샘플" 표기는
틀렸습니다. 곡 길이가 필요하면 `_jiA` 나 `_xe` 를 쓸 것.

### 오디오 후킹

| 후킹 | 시그니처 | 용도 | 1.0.4b (2026-09-23) |
|---|---|---|---|
| `SongSelectScene._co(_Cg)` | 참조형 1개 | 곡 목록 프리뷰 오디오 **로드 완료** 콜백 | 동작 |
| `GameScene._dK(_Cg)` | 참조형 1개 | 플레이 씬 메인 BGM 로드 | **`_dK` 없음** — 같은 시그니처 `GameScene._IK(_Cg)` 가 새로 생김(이름 변경 추정, 미검증) |
| `_Dg._KiA(float, double)` | 값형 | BGM 재생 트리거 (볼륨, 시작 오프셋) | 미확인 |

셋 다 [04번 문서](04-후킹-함정과-성능.md)의 안전 조건을 만족합니다.

`_co` 는 **로드에 성공해야만** 불립니다. 그래서 "게임이 이 음원을 열 수 있었는가"를 판정하는
신호로 쓸 수 있습니다(아래 A 테스트).

### FMOD 구조 — 게임은 FMOD를 직접 쓰지 않는다

커스텀 음원이 막히는 이유는 FMOD가 아니라 **lowiro가 FMOD 위에 얹은 자체 네이티브 레이어**입니다.

```
_zf  (오디오 매니저, static _psA)
 └─ _Cg  (핸들) — ctor(IntPtr sound, int assetReferenceId, string friendlyName, _Yf loadParams)
     └─ ifapp_fmod_native.dll  (lowiro 자체 제작, Plugins/x86_64)
         └─ FMOD Core  (fmodstudio.dll)
```

| 근거 | 의미 |
|---|---|
| 스트리핑된 `Il2CppFMOD.System` 에 `setFileSystemRaw` 가 남아 있음 | 게임이 **FMOD 파일 I/O 콜백을 갈아끼움** (안 쓰면 스트리핑됐을 것) |
| `ifapp_fmod_native` export: `get_file_open/close/async_read/async_cancel_callback` | 그 콜백의 주인 |
| `ifapp_fmod_native_async_complete_transform` | 읽은 바이트에 **변환(복호화)** 을 적용 → `sam/` 오디오가 전부 암호화돼 있는 이유 |
| `ifapp_fmod_clock_tracking_*` + `FMOD5_ChannelGroup_GetDSPClock` 임포트 | `_miA` 재생 시계의 출처 |
| `_IF._NGA(int assetId, _BF) : Sound` | Sound 를 **에셋 ID로** 만든다 → 파일 이름 대신 lowiro 규칙의 키를 쓸 가능성 |
| Player.log `[FMOD] FmodNativeBridge initialized (ABI v16)` | 게임 자체 FMOD 로그가 Player.log 에 남는다 |

그 밖에 쓸 만한 멤버 (전부 `Il2Cpp_J`):

| 멤버 | 타입 | 비고 |
|---|---|---|
| `_IF._ZSA` | `Il2CppFMOD.System` (static) | **게임이 쓰는 FMOD System 그 자체** |
| `_IF._ctA` | `ConcurrentDictionary<int, Sound>` | **에셋 ID → 진짜 `Sound` 캐시** (확인됨, 아래) |
| `_Cg._B` | `IntPtr` | **진짜 `FMOD::Sound*`** = `_IF._ctA[_SUA].handle` (확인됨) |
| `_Cg._A` | `IntPtr` | **FMOD Channel 핸들**로 추정 (Sound 가 아님) |
| `_Cg._b` | `IntPtr` | 미상 (`0xF` 고정) |
| `_Cg._c` | `int` | `_SUA` 와 같은 에셋 ID |
| `_zf._uFA(string, _IF._jF, Action<_Cg>, …)` | `_Cg` | 논리 경로로 로드. `CallerCount(19)`, 주 진입점으로 보임 |

> **`_Cg._A` 는 `FMOD::Sound*` 가 아니다.** 로그에 `_A = 0x7FA000D`, `_b = 0xF` 가 찍혔는데
> 홀수라서 힙 포인터가 될 수 없습니다. `BgmHook` 의 "네이티브 FMOD::Sound* 핸들" 로그 표기는 틀렸습니다.
>
> 2026-09-23 `FmodProbe` 로 대조한 결과 (alamode 프리뷰, 1.0.4b):
>
> ```
> _Cg: _SUA=5610, _A=0x7FE000D, _b=0xF, _B=0x1F852DB2CD8, _c=5610, _D=False
> _IF._ctA 개수: 2
> _ctA[5610]  → Sound 0x1F852DB2CD8, 길이 135.669초     ← _B 와 같은 값. 길이는 _jiA(135.669) 와 일치
> 모드가 playSound 로 받은 Channel 핸들: 0x7F40009       ← _A 와 같은 0x7Fx000y 모양
> ```
>
> 즉 **`_B` 가 Sound**, `_ctA` 는 AssetId 를 키로 쓰는 Sound 캐시, `_A` 는 FMOD 의 인코딩된 Channel 핸들입니다.

|---|---|---|---|

| **B. FMOD 직접** | `_IF._ZSA` 로 Sound 를 직접 만들고 게임 핸들에 끼워 넣기 | 보통~어려움 | **1단계(직접 재생) 성공**, 끼워 넣기 미시도 |

| D. 암호화 재현 | `ifapp_fmod_native.dll` 의 transform 을 역공학해 OGG 를 암호화 | 어려움 | 미시도 — 파일별 키라 네이티브 분석 필요 |

#### A 테스트 결과 (2026-09-23, 1.0.4b)

**조건.** `alamode.wav`(`89523571a0aaeb247ac449748a0fd876`)를 평문 OGG로 교체했습니다.
Vorbis q4, 48kHz 스테레오를 원본과 같은 **3,319,480 바이트**가 되도록 뒤에 0을 채워
`FileLength` 검사 변수를 없앴습니다. 원본은 같은 폴더에 `.orig` 로 백업해 뒀습니다.

**결과:**

- 부팅은 정상입니다. 시작할 때 파일 무결성 검사는 없습니다.
- 곡 선택에서 alamode 를 고르면 핸들(`_vr`, `_d` = 교체한 GUID)은 생깁니다.
  하지만 **로드 완료 콜백 `_co` 가 두 번 다 오지 않았습니다.** 같은 세션에서 원본 파일인
  `bethere.wav` 는 선택 0.3초 뒤에 `_co` 가 불렸습니다.
- Player.log 에는 FMOD 에러가 남지 않습니다. **조용히 실패합니다.**
- 인게임 청각 확인: **프리뷰 무음.** 노이즈도 원곡도 아닙니다.
- 테스트 뒤 원본을 복구했습니다(SHA-256 일치 확인). `.orig` 백업은 다음 테스트용으로 남겨 뒀습니다.

**해석.** 크기를 맞췄으므로 `FileLength` 때문은 아닙니다. lowiro 의 `async_complete_transform` 이
평문 OGG 까지 "복호화"해서 깨뜨린 것으로 봅니다. 즉 **`sam/` 에 넣는 파일은 반드시 lowiro 방식으로
암호화돼 있어야 하고**, 파일 교체만으로는 커스텀 음원을 넣을 수 없습니다.

#### B 경로 메모 — 콜백 우회 플래그가 있다

인터롭의 `Il2CppFMOD.CREATESOUNDEXINFO` 는 이 게임 FMOD 버전 레이아웃 그대로인 **blittable struct**입니다.
여기에 FMOD 공식 필드 **`ignoresetfilesystem`** 이 있습니다. 이걸 켜면 이 Sound 하나만 lowiro 파일 콜백을
건너뛰고 OS 파일 I/O 로 직접 읽습니다.

```csharp
var ex = new CREATESOUNDEXINFO {
    cbsize = Marshal.SizeOf<CREATESOUNDEXINFO>(),
    ignoresetfilesystem = 1,
};
_IF._ZSA.createSound(@"...\hwa\music.ogg", MODE.CREATESTREAM | MODE.ACCURATETIME, ref ex, out Sound snd);
```

모드 → IL2CPP 방향 **호출**에서 쓰는 ref/out 은 [04번 문서](04-후킹-함정과-성능.md)의 byref 후킹 크래시와 무관합니다
(그건 IL2CPP → 모드 방향 트램펄린 문제).

#### B 1단계 결과 — 게임 FMOD 로 `hwa/music.ogg` 직접 재생 (2026-09-23, 1.0.4b)

`FmodProbe.cs` 가 곡 선택 화면에 들어갈 때 위 코드로 Sound 를 만들고 마스터 채널 그룹에 `playSound` 합니다.

```
게임 FMOD System 핸들: 0x1F8528D2B58
createSound(ignoresetfilesystem=1, cbsize=224) → OK
  ├ Sound 핸들: 0x1F852DB2B48          ← 진짜 힙 포인터
  ├ 길이: 158.016초                    ← ffprobe 측정값(158.016375초)과 일치
  └ playSound(마스터 그룹) → OK, Channel 핸들: 0x7F40009
```

**lowiro 복호화 콜백을 건너뛰고 평문 OGG 를 여는 데 성공했습니다.** 인게임 청각 확인: 게임 프리뷰 위에
`music.ogg` 가 **겹쳐서 들렸습니다.** 크래시도 없었고, 곡 선택을 떠날 때
`Sound.release()` 로 정리한 뒤 게임을 정상 종료했습니다. 1.0.4b 래퍼에는 `Channel.stop` 이 없으므로
정지는 `Sound.release()` 로 합니다(해제하면 그 Sound 를 틀던 채널도 멈춤).

#### 다음: 끼워 넣기 (3단계)

위 대조 결과로 후보가 좁혀졌습니다:

1. **`_IF._ctA[assetId]` 선점** — 게임이 캐시를 먼저 보는 구조라면, alamode 로드 전에 우리 Sound 를
   5610 에 넣어 두면 게임이 자기 파이프라인(자기 채널 그룹, 자기 `_miA` 시계)으로 우리 음원을 틉니다.
   데이터만 바꾸는 방식이라 이 프로젝트의 "후킹보다 자료구조 직접 수정" 원칙에 맞습니다.
2. **`_Cg._B` 교체** — 로드가 끝난 핸들의 Sound 를 갈아끼웁니다. 다만 채널(`_A`)은 이미 원본으로
   재생 중일 수 있어서 1번이 안 될 때의 차선책입니다.

어느 쪽이든 원본 Sound 를 `release` 할지, 게임이 나중에 해제할 때 우리 Sound 를 해제해도 되는지를
같이 확인해야 합니다.

## 3. 세이브 데이터

```
C:\Users\<user>\AppData\LocalLow\lowiro\infalsus\<SteamID64>\release\savestate_V3.sav
```
