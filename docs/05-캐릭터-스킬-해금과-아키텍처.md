# 05. 캐릭터 · 스킬 해금과 아키텍처

[← 문서 목록](README.md)

2026-09-10 인게임 Hub 화면의 캐릭터 선택 레이어(`CharacterSelectLayer`)에서 **모든 캐릭터의 잠금 해제, 좌우 네비게이션 순환, 선택(SELECT) 활성화, 스킬 레벨 조작**이 실측 검증되었습니다.

---

## 1. 캐릭터 선택 레이어 구조 (`CharacterSelectLayer`)

Hub 화면의 캐릭터 선택 버튼을 누르면 활성화되는 최상위 UI 레이어입니다 (`HubScene.characterSelectLayer`).

```
HubScene
  └─ characterSelectLayer (CharacterSelectLayer)
       ├─ centerCharacterContainer / leftCharacterContainer / rightCharacterContainer
       ├─ leftButton / rightButton (CharacterSelectNavButton)
       ├─ selectButton (MainActionButton)
       ├─ storyActiveWidgets : CharacterSelectStoryActiveWidget[5]     ← 활성 캐릭터 초상화/일자
       ├─ storySelectedWidgets : CharacterSelectStorySelectedWidget[5]  ← 현재 선택된 슬롯
       ├─ storyDisabledWidgets : Constrained2D[5]                       ← "???" 잠금 마스크
       ├─ _Dl / _el / _El : CharacterSkillLevels[]                      ← 캐릭터별 스킬 레벨
       └─ _fl / _Fl : GlobalSkillLevels                                 ← 공용 스킬 레벨
```

### 1) 캐릭터 식별자 (`CharacterIdentifier`)

전체 캐릭터 열거형은 `Il2Cppifapp.Game.Data.CharacterIdentifier`에 100% 무손상으로 보존되어 있습니다:

```csharp
public enum CharacterIdentifier
{
    Nia = 0,     // 기본 지급 캐릭터 (하단 슬롯 0)
    Mei = 1,     // 하단 슬롯 1
    Ayame = 2,   // 하단 슬롯 2
    Iris = 3,    // 하단 슬롯 3
    Story = 4,   // (또는 Freya/Touko 등 플레이어블 캐릭터)
    Freya = 5,
    Touko = 6,
    ...
}
```

### 2) 하단 5개 슬롯의 정체

화면 좌측 하단에 위치한 5개의 육각형 위젯은 **플레이어블 캐릭터들의 타임라인/스토리 진행 상태**를 나타냅니다:
* **`storyActiveWidgets`**: 해금된 캐릭터의 얼굴 초상화, 연/월/일(예: 10277 / Month 8 / Day 27 / Noon) 표시.
* **`storySelectedWidgets`**: 현재 화면 중앙에 선택되어 있는 캐릭터의 핑/포커스 마커.
* **`storyDisabledWidgets`**: 미해금 상태일 때 위젯 위를 덮는 **검은색 육각형 + "???"** 잠금 오버레이.

초기 상태에서는 `Nia(0)`만 해금되어 있어 1번 슬롯만 켜지고, 나머지 2~5번 슬롯은 `storyDisabledWidgets`로 가려져 있습니다. 또한 좌우 화살표 네비게이션 버튼이 다음/이전 해금 캐릭터를 찾지 못해 양쪽 모두 **"NIA"**로 고정됩니다.

## 2. 해금 메커니즘 분석

### 1) 핵심 메서드: `CharacterSelectLayer._KI(CharacterIdentifier)`

캐릭터 선택 레이어 내부에서 캐릭터가 사용 가능한 상태(해금 여부)인지를 판단하는 핵심 정적 메서드입니다:

```csharp
// Il2Cppifapp.Game.Scenes.CharacterSelectLayer
[CallerCount(10)]
public static bool _KI(CharacterIdentifier identifier);
```

* **시그니처 안전성**: `CharacterIdentifier`는 4바이트 정수 기반 enum 값형(by value)이므로, [04번 문서](04-후킹-함정과-성능.md)의 `byref` 트램펄린 크래시 위험이 전혀 없는 **100% 안전한 후킹 대상**입니다.
* **동작 원리**:
  - 좌우 네비게이션 버튼(`leftButton`, `rightButton`)이 다음/이전 캐릭터를 탐색할 때 `_KI`를 순회 호출합니다.
  - 하단 슬롯 초기화 시에도 각 캐릭터의 `_KI` 결과에 따라 활성 위젯과 "???" 마스크의 표시 여부가 결정됩니다.
* **해금 방법**: Harmony Prefix로 가로채어 항상 `true`를 돌려줍니다.
  ```csharp
  [HarmonyPatch(typeof(CharacterSelectLayer), nameof(CharacterSelectLayer._KI))]
  private static class Patch_CharacterSelectLayer_IsUnlocked
  {
      [HarmonyPrefix]
      public static bool Prefix(CharacterIdentifier __0, ref bool __result)
      {
          __result = true;
          return false; // 원본 실행 생략, 무조건 해금
      }
  }
  ```

### 2) 선택 버튼 활성화: `CharacterSelectLayer._LI()`

현재 표시된 캐릭터를 최종 선택(SELECT)할 수 있는지 검사하는 인스턴스 메서드입니다:

```csharp
// Il2Cppifapp.Game.Scenes.CharacterSelectLayer
public bool _LI();
```

* `_KI`와 마찬가지로 Prefix에서 `__result = true; return false;`로 후킹하면, 미해금 상태이거나 스토리 진행 조건을 만족하지 못한 캐릭터라도 **SELECT 버튼이 상시 활성화**되어 선택이 가능해집니다.

### 3) 런타임 UI 잠금 오버레이 직접 제거

후킹과 더불어 레이어 틱(`Tick`) 시점에 UI 요소를 직접 제어하면 화면이 즉시 갱신됩니다:

```csharp
// 1. "???" 잠금 마스크 비활성화
foreach (var mask in layer.storyDisabledWidgets)
{
    if (mask != null && mask.gameObject.activeSelf)
        mask.gameObject.SetActive(false);
}

// 2. 캐릭터 초상화/정보 강제 표시
foreach (var widget in layer.storyActiveWidgets)
{
    if (widget != null && !widget.gameObject.activeSelf)
        widget.gameObject.SetActive(true);
}

// 3. 버튼 활성화
layer.selectButton?.gameObject.SetActive(true);
layer.selectButton?.button?._BSA(true); // interactable
```

## 3. 스킬 구조체 및 레벨 조작

`CharacterSelectLayer`는 캐릭터 스킬 및 공용 스킬 데이터를 메모리에 직접 들고 있으며, 이 구조체들은 `Game.Data` 소속이라 **필드명이 100% 온전하게 보존**되어 있습니다.

### 1) 캐릭터 전용 스킬 (`CharacterSkillLevels`)

```csharp
// Il2Cppifapp.Game.Data.CharacterSkillLevels (struct)
public struct CharacterSkillLevels
{
    public byte Infusion;                  // 스펙트럴 스킬 (Infusion)
    public byte Synesthesia;               // 공감각
    public byte ExpandedIotaLimit;         // 캐릭터 스킬: 이오타 한도 확장
    public byte OutOfBoundsTolerance;      // 이탈 허용치
    public byte OverlapTolerance;          // 중첩 허용치
    public byte DisconnectionTolerance;    // 캐릭터 스킬: 연결 해제 허용치
    public byte AugmentResolve;            // 증강 결의
}
```

* `layer._Dl`, `layer._el`, `layer._El` 배열에 캐릭터별 스킬 레벨이 들어 있습니다.
* `struct`이므로 인덱서로 읽은 사본의 필드를 수정한 뒤 **반드시 배열 인덱서에 되써넣어야 합니다** ([04번 문서](04-후킹-함정과-성능.md) 4장).

```csharp
for (int i = 0; i < arr.Length; i++)
{
    var skill = arr[i];
    skill.Infusion = 5;
    skill.ExpandedIotaLimit = 5;
    skill.DisconnectionTolerance = 5;
    ...
    arr[i] = skill; // 되써넣기 필수
}
```

### 2) 글로벌 공용 스킬 (`GlobalSkillLevels`)

```csharp
// Il2Cppifapp.Game.Data.GlobalSkillLevels (struct)
public struct GlobalSkillLevels
{
    public byte DiscoveryBoost;              // 발견 부스트
    public byte IntuitionBoost;              // 직관 부스트
    public byte CardInventoryExpansion;      // 카드 인벤토리 확장
    public byte IotaRetrievalBoost;          // 이오타 회수 부스트
    public byte IotaStackBoost;              // 이오타 중첩 부스트
    public byte IotaPotencyBoost;            // 이오타 위력 부스트
    public byte IotaPotencyMaximization;     // 이오타 위력 극대화
}
```

* `layer._fl`, `layer._Fl` 프로퍼티에 접근하여 원하는 레벨(예: 5)을 직접 대입하면 즉시 반영됩니다.

## 5. 결론 및 주의사항

1. **`_KI`는 값형 enum 인자라 안전합니다**: `ref struct`나 포인터 트램펄린이 아니므로 Harmony 후킹으로 인한 크래시 위험이 없습니다.
2. **UI 마스크(`storyDisabledWidgets`)도 함께 꺼야 깔끔합니다**: 후킹만으로는 이미 렌더링된 "???" 비활성 마스크가 그대로 남아 있을 수 있으므로, 틱 루프에서 `SetActive(false)` 처리를 병행해야 초상화가 가려지지 않고 깔끔하게 드러납니다.
3. **스킬 구조체는 복사본에 주의**: `CharacterSkillLevels`는 struct이므로 배열 인덱서 수정 후 반드시 다시 대입해야 게임 엔진에 정상 반영됩니다.
