# 01. 차트 포맷과 에셋

[← 문서 목록](README.md)

## 1. 차트는 두 포맷이 존재합니다

| | 개수 | 상태 | 매핑 등록 |
|---|---:|---|---|
| 텍스트 소스 (`chart(...)`) | 646 | 평문 | **없음 — 빌드 잔재** |
| `.spc` 바이너리 | 283 | 12바이트 헤더 + 패킹된 노트 | 등록됨 (게임이 실제 로드) |

`.spc` 283개 전부를 매핑 GUID로 대조한 결과 **평문은 0개**입니다. 즉 게임은 바이너리만 읽습니다.

> **2026-09-23 재확인 (1.0.4b):** 텍스트 소스 646개는 이제 `sam/` 에 **없습니다.** 업데이트 때
> 매핑 밖 잔재가 통째로 지워졌습니다([4장](#4-에셋-레이아웃)). 아래 스펙은 예전에 떠 둔 기록입니다.
아래 텍스트 포맷 스펙은 **저작 포맷을 이해하는 용도**로는 그대로 유효하지만, 이 텍스트를 `sam/`에
넣는다고 게임이 읽지는 않습니다.

## 2. 텍스트 저작 포맷 (잔재 646개)

`infalsus_Data/StreamingAssets/sam/` 안에 평문으로 남아 있습니다.

```
chart(140.00,4.00)
lane(0,4,0)
tap(3429,1,1)
hold(8571,3,1,1286)
flick(23571,6,12,6,4)
skyarea(24000,13,16,6,3,16,6,1,1,857,20)
```

### 시간 단위

**전부 밀리초 절대시간**입니다. 마디/박 환산은 익숙한 그 식 그대로:

```
1마디(4/4) = 240000 / BPM  ms
1박        =  60000 / BPM  ms

ms = 마디번호 × 240000 / BPM
```

검증 (`chart(140.00,4.00)`, 1마디 = 1714.29ms):

| 이벤트 | ms | 마디 |
|---|---:|---:|
| `tap(3429,...)` | 3429 | 2.000 |
| `hold(8571,...)` | 8571 | 5.000 |
| `tap(17143,...)` | 17143 | 10.000 |

전체 429,634개 노트의 1/16마디 격자 정합성 중앙 오차 0.0033 — 정수 ms 반올림 오차 수준이라
격자 정렬이 확인됩니다.

### 명령어 전수 (646개 차트, 43만 노트 기준)

| 명령어 | 시그니처 | 개수 |
|---|---|---:|
| `chart` | `(bpm, beatsPerMeasure)` | 646 |
| `bpm` | `(ms, bpm, beatsPerMeasure[, 1])` | 3,833 |
| `lane` | `(ms, mask, flag)` | 3,262 |
| `track` | `(ms, value)` | 3,536 |
| `tap` | `(ms, type, lane)` | 158,914 |
| `hold` | `(ms, lane, type, durationMs)` | 49,489 |
| `flick` | `(ms, pos, denom, width, dir)` | 103,555 |
| `skyarea` | `(ms, x1,d1,w1, x2,d2,w2, ease1, ease2, durationMs, group)` | 117,676 |

### 인자 값 범위 (실측)

- `chart` arg0 BPM `60~282`, arg1 박자 `4.00`이 622/646 (`3.50`/`6.00`/`99`/`999`도 존재)
- `tap` / `hold` — **lane `0~5` (6레인)**, **type `1~4`**
  `tap`은 `(ms, type, lane)` 순, `hold`는 `(ms, lane, type, dur)` 순으로 **자리가 뒤바뀌어 있음**.
  값 범위로 구분 가능 (0~5면 레인, 1~4면 타입)
- `flick` arg4 `dir`은 **`4` 또는 `16` 두 값뿐** (51,952 / 51,603 — 거의 반반). 방향 플래그로 보임
- `flick`/`skyarea`의 `denom`은 `12`가 압도적, 다음이 `24`, `16`, `32` — 화면 가로를 n등분한 좌표계
- `skyarea` ease `0/1/2` 세 종류, arg10은 그룹 ID (같은 값끼리 하나의 스카이 레일로 연결)
- `bpm` 4번째 인자는 전부 `1` (상수)
- `lane(ms, mask, flag)` — **동적 레인 변형 (4키 ↔ 3키 전환 기믹)** (634개 차트 전수 조사 확정)
  - 하단 레인 4키 기본 배치: `1번=A`, `2번=S`, `3번=D`, `4번=F` (0번/5번은 외곽 영역)
  - `mask`는 **`1`과 `4`** 두 가지만 사용:
    - `lane(ms, 1, 1)`: 맨 왼쪽 1번 레인(`A` 키) **비활성화(닫힘)** → **`S, D, F` 3키 모드로 전환**
    - `lane(ms, 1, 0)`: 1번 레인(`A` 키) **다시 활성화(열림)** → `A, S, D, F` 4키 모드로 복귀
    - `lane(ms, 4, 1)`: 맨 오른쪽 4번 레인(`F` 키) **비활성화(닫힘)** → **`A, S, D` 3키 모드로 전환**
    - `lane(ms, 4, 0)`: 4번 레인(`F` 키) **다시 활성화(열림)** → `A, S, D, F` 4키 모드로 복귀
  - 런타임 구현: `LogicalNotePlayer._ve._zC : Memory<_eA>` 이벤트 버퍼에 적재되어, `Track` 렌더러가 해당 시간에 `visualLaneDisableMarkerPrefab` / `visualLaneEnableMarkerPrefab` 마커를 띄우고 `keyPressedIndicators` 및 레인 판정을 실시간 온/오프함.

### 런타임 자료구조와의 대응

**저작 포맷의 `denom`(분모) 좌표계가 런타임에 그대로 살아 있습니다.** [02번 문서](02-런타임-차트-주입.md)의
`_BA(int num, int denom)` 가 바로 이것이고, 하단 노트는 분모 4, 스카이 노트는 분모 12/16 계열을 씁니다.

## 3. `.spc` 바이너리 포맷

283개 전부 **동일한 12바이트 헤더**로 시작합니다 (`b9 55 78 7a 7c 9e df a5 a0 16 08 4b`).
그 뒤는 패킹된 노트 데이터.

파서 진입점이 특정됐습니다 — 난독화 와중에도 **함수 이름 두 개가 안 깨졌습니다**:

```csharp
// Il2Cpp_n._S  (Il2CppGame.dll)
[CallerCount(1)]
public static ValueTuple<_t, List<_fA>, List<_eA>> _Gab(ReadOnlySpan<byte> data, string name);

[CallerCount(1)]
public static void DecodeNotes(byte* data, int noteCount, _Z* initialState, _fA* output);  // ← 이름 살아있음

public static _Z _Ab(string, int, UInt16);   // 디코드 초기 상태 = f(chartId, ?, SongId)

// Il2Cpp_b._R  (파싱 결과 홀더)
public _R(ValueTuple<_t, List<_fA>, List<_eA>> logicalChart, string sourceText);  // ← 파라미터 이름 살아있음
```

`DecodeNotes`가 `noteCount` + `initialState`를 받고, 주변에 델타 디코드로 보이는 헬퍼
(`_Mab(long, ref _Z, int, int)`, `_Oab`, `_qab`)가 붙어 있는 것으로 보아
**암호화가 아니라 델타+비트패킹 압축**입니다. 초기 상태를 곡 ID로 시드하기 때문에 파일마다
스트림이 달라 고엔트로피로 보였던 것.

> **인코더를 쓸 필요도, 파서를 후킹할 필요도 없습니다.**
> `_Gab` 은 `ReadOnlySpan<byte>` 인자 때문에 후킹하면 크래시합니다
> ([04번 문서](04-후킹-함정과-성능.md)). 게임이 원본을 평소대로 파싱하게 두고
> **파싱 이후의 런타임 자료구조를 직접 고치는 것**이 실제로 동작하는 경로입니다
> ([02번 문서](02-런타임-차트-주입.md)).

## 4. 에셋 레이아웃

`infalsus_Data/StreamingAssets/sam/` — 파일명은 32자리 GUID. **업데이트로 구성이 바뀌었습니다:**

|---|---:|---:|---|
| 2026-09-10 (1.0.3 이전) | 12,085 | 2.3 GB | 고엔트로피 10,348 + 평문 텍스트 1,172 + OGG 565 |
| **2026-09-23 (1.0.4b)** | **10,346** | **1.3 GB** | **매핑 엔트리 수와 정확히 일치. 평문 0개** |

같은 종류끼리 헤더가 같으면 고정 키, 다르면 파일별 키/시드입니다. 오디오는 후자라

| `.ogg` | 394 | 용도 미확인 — **평문 아님** (위 스캔) |

> **초판 정정.** "곡 오디오는 평문 `.ogg`" 는 틀렸습니다. 게임이 실제로 여는 곡 음원은
> **`<곡슬러그>.wav`** 입니다. 예: `alamode` 는 `alamode.wav` → `89523571a0aaeb247ac449748a0fd876`
> (AssetId 5610, 3,319,480 바이트)이고, 곡 선택 프리뷰와 플레이 씬 둘 다 이 파일을 씁니다.

| `.spc` | 283 | **차트** |
| `.sps` / `.spi` / `.spp` | 236 / 52 / 2 | 스토리 스크립트 계열 |

논리 경로 규칙이 아주 단순합니다:

```

alamode1.spc → ca4ac26d9e569ed4b8774fdae3ddb55a   (Evolved)
alamode2.spc → 4e8c93a5a4f48f14c9d98087e0aa2b6d   (Ultimate)
alamode3.spc → 8b78561461b959543bdaa269a3a13702   (Forbidden)
```

즉 **`<곡슬러그><난이도인덱스>.spc`**. 난이도 인덱스는 `ChartDifficultyFlag` 순서
(Minimal=1 / Evolved=2 / Ultimate=4 / Forbidden=8 — **플래그 값이지 인덱스가 아니므로 주의**).

이 규칙이 런타임에도 그대로 유효합니다. `LogicalNotePlayer._Ve` 가 `alamode0.spc` 를 돌려주고,
확장자를 떼면 `SongChartInfo.Id` (`alamode0`) 와 정확히 일치합니다.

`FileLength`가 매핑에 박혀 있고 283건 전부 실제 크기와 일치하므로, **길이가 다른 파일로 덮어쓰면
로더가 거부할 가능성이 높습니다.** 파일 교체보다 런타임 수정이 안전합니다.

sam 12,085개 중 매핑된 건 10,346개고, 나머지 1,739개(평문 차트 646 + 스토리 텍스트 등)는
**매핑 밖 잔재**입니다.

## 5. 곡 메타데이터

`SongInfo` / `SongChartInfo` 는 `Game.Data` 소속이라 필드명이 전부 살아 있습니다.

```csharp
public sealed class SongInfo : ValueType {   // ← ValueType 상속(구조체)임에 주의
    public SongId Id;                        // .Value 로 int 접근
    public string BaseName;                  // 'alamode' (표시 제목이 아닌 슬러그)
    public CharacterIdentifier CharacterIdentifier;
    public SongChartInfo[] ChartInfos;
    public float PreviewStartSeconds, PreviewEndSeconds;
    ...
}

public sealed class SongChartInfo : ValueType {
    public string Id;                        // 'alamode0'
    public bool Available;
    public ChartDifficultyFlag Difficulty;
    public string DisplayChartDesigner, DisplayJacketDesigner;
    public int Rating;                       // 표시 레벨
    public string LevelSectionIndicator;     // 용도 미확정 — 아래 참고
}
```

접근 경로: `<Scene>.dataAccess.SongData.allSongInfo`

### `Rating` 과 `LevelSectionIndicator` 를 이어붙이지 말 것

두 값을 이어 출력하면 `Lv.11` 이 **Rating 11** 인지 **Rating 1 + 접미 '1'** 인지 구분이 안 됩니다.
분리해서 찍어보니 답은 후자였습니다:

```
alamode0 (Minimal) → Rating: 1, LevelSectionIndicator: '1'
UI DifficultyValueText → '1'
```

**화면에 표시되는 레벨은 `Rating` 단독**입니다. `LevelSectionIndicator` 는 값이 우연히 같았을 뿐
별개 필드이고 용도는 미확정입니다 — `+` 표기가 붙는 상위 난이도를 한 번 찍어보면 갈립니다.

### UI 슬롯 개수를 가정하지 말 것

`SongInfoContainer` 의 텍스트 슬롯은 종류마다 개수가 다릅니다.

| 필드 | 슬롯 수 | 구성 |
|---|---:|---|
| `songTitle` | 2 | `SongTitleShadow`, `SongTitle` |
| `songArtist` | 2 | `SongArtistShadow`, `SongArtist` |
| `difficultyNameText` | 1 | `DifficultyText` |
| `difficultyLevelText` | 1 | `DifficultyValueText` |

`[0]` 만 읽으면 그림자 슬롯을 읽게 되는 경우가 생깁니다. 배열을 전부 순회할 것.

또한 자켓/제목이 프리팹 더미(`Song Name`, 텍스처 `white`)인 동안 읽으면 쓰레기 값이 나옵니다.
실제 값이 채워질 때까지 기다리는 로직이 필요합니다.

## 6. 자켓

자켓은 곡마다 **Addressable Material 두 개**입니다. 텍스처가 아니라 머티리얼 단위로 관리됩니다.

```csharp
// Il2Cppifapp.Game.Data.SongData  (<Scene>.dataAccess.SongData)
public AssetReferenceT<Material> FallbackJacketLargeMaterial, FallbackJacketSmallMaterial;
public SongJacketEntry[] songIdJacketMaterials;             // SongId → (Large, Small)
public SongDataChartJacketEntry[] chartIdJacketMaterials;   // 차트 ID('alamode0') → (Large, Small) — 난이도별 자켓
```

alamode 실측(2026-09-23~24):

| 머티리얼 | 텍스처 | 쓰는 곳 |
|---|---|---|
| `alamode` (Large) | `alamode` 2048x2048 | 곡 선택 큰 카드(`LargeSongCard.jackets`) |
| `alamode_small` (Small) | `alamode_small` 256x256 | 곡 목록 작은 카드, 플레이 화면(`SongInfoContainer.jacket`) |

게임은 불러온 머티리얼을 UI(`Constrained2D`)에 **그대로** 꽂습니다(`_H` 이름이 `alamode`).
반면 곡 선택 배경(`SongSelectJacketBacking`)과 로딩 화면(`JacketTriangleMask Variant`)은
자기 머티리얼에 **텍스처만 옮겨** 씁니다. 로드 전에는 `WhiteMat` / 텍스처 `white` 가 들어 있습니다.

### 교체 방법 — 텍스처 내용을 덮어쓴다 (`JacketInjector.cs`)

머티리얼을 갈아 끼우면 텍스처만 옮겨 쓰는 곳이 원본으로 남습니다. 그래서 **게임 텍스처 객체는 그대로 두고
내용만 PNG 로 바꿉니다** (`ImageConversion.LoadImage`). 그 텍스처를 참조하는 곳이 전부 같이 바뀝니다.
압축 텍스처에 불러도 `ARGB32` 1024x1024 로 바뀌며 잘 들어갔습니다.

감지는 `Constrained2D._irA(Material, bool)` postfix — UI 에 머티리얼을 꽂는 함수(호출부 432곳)입니다.
머티리얼 이름이 `<슬러그>` / `<슬러그>_small` 이면 `mainTexture` 를 교체합니다.
판정 결과는 인스턴스 ID 로 캐시합니다(포인터는 파괴 후 재사용될 수 있음).

**2026-09-24 인게임 확인 (사용자 육안):** 허브 → 곡 선택 진입 순간 `_irA` 가 작은 자켓과 큰 자켓을 둘 다 먼저 잡았고,
곡 선택 작은/큰 카드·배경 자켓·로딩 화면·플레이 화면이 전부 커스텀 자켓으로 나왔습니다.
난이도를 바꾸거나 플레이 씬으로 넘어가도 게임이 같은 텍스처를 다시 써서 원본으로 돌아가지 않았습니다.
결과 화면은 이번 테스트에서 가지 않아 미확인입니다.

## 7. 배경 영상 (BGA)

일반 플레이 씬(`GameScene`)에는 VideoPlayer 가 없습니다. 배경은 `GameScene.backgroundObject` 하나이고,
이 `Constrained2D` 가 화면 전체를 덮는 **불투명 메시**입니다. alamode 실측(2026-09-24):

| 항목 | 값 |
|---|---|
| 오브젝트 / 레이어 | `BackgroundObject` / 6 |
| 머티리얼 / 셰이더 | `Mindscape2-Light` / `Unlit/StenciledUnlitSpriteOpaque` (렌더 큐 2000) |
| 텍스처 | `Mindscape2-Light` 4096x2048, 타일링 (1,1) 오프셋 (0,0) |
| 크기 | 3840x2160px, 타입 `Sprite`, 월드 34.64x19.49 (16:9) |

카메라는 `CameraPerspective` 하나(원근 FOV 60, Near 0.3 ~ Far 1000, culling `0x7DF7` — 레이어 6 포함)입니다.
`GameScene.gameCamera` 의 `'GameCamera'` 는 Camera 가 아니라 `Transform`(카메라를 움직이는 부모)입니다.
게임은 URP Render Graph(Unity 6000.3.9f1)를 씁니다.

### 교체 방법 — 영상을 배경 머티리얼에 꽂는다 (`VideoInjector.cs`)

게임 자체 영상 플레이어 `C2DVideoPlayer`(`videoPlayer` + `targetOutput: Constrained2D` + `RenderTexture` + `Material`)와
같은 구조입니다.

1. 카메라 오브젝트에 VideoPlayer 추가 — `renderMode = RenderTexture`, 소리 끔, `timeReference = ExternalTime`.
2. 준비가 끝나면 영상 크기로 `RenderTexture` 를 만들어 `targetTexture` 로 연결.
3. 재생이 시작되면 배경 머티리얼(`_H`)을 복제해 `mainTexture` 를 그 텍스처로 바꾸고 `backgroundObject._irA(복제본)`.
4. 매 프레임 `externalReferenceTime = _Dg._miA()`(곡 재생 위치, 초).

`_irA` 는 넘긴 머티리얼을 복제 없이 쓰지만 **`_H` 에는 다음 프레임에 반영됩니다.** 호출 직후 `_H` 를 읽으면 원래 머티리얼이 나옵니다.

대상 곡은 처음엔 alamode 였고, 새 곡 슬롯(8장)이 생긴 뒤 `hwa` 로 옮겼습니다 — 원곡은 영상 없이 원래대로입니다.

**2026-09-24 인게임 확인 (스크린샷 + 사용자 육안, alamode 대상일 때):** 1920x1080 24fps 영상이 배경 전체에 16:9 로 깔리고
노트·레인·UI 는 그 위에 그려졌습니다. 싱크 오차는 5초 -10ms / -2ms, 30초 -3ms(프레임 720 = 30×24).
재시작하면 씬이 다시 만들어지는데, 정리 후 다시 붙이는 흐름이 정상 동작했습니다(두 번째 준비 0.12초).
Player.log 에 "H.264 가 baseline 프로파일이 아니라 타임스탬프를 보정한다"는 경고가 나오지만 싱크에는 영향이 없었습니다.

### 미해결 — alamode 플레이 중 종료하면 게임이 멈춤

alamode 를 플레이하다 일시정지 메뉴에서 게임을 끄면(3회, 07:21·07:37·07:43) Player.log 가 `[FMOD] AudioManager_SystemShutdown`
에서 끊기고 게임이 CPU 코어 하나를 잡은 채 응답 없음이 됩니다. `OnApplicationQuit` 에서 영상을 멈추고 렌더 텍스처를 풀어도 같았습니다.

| 대조 (같은 모드) | 결과 |
|---|---|
| 곡 선택 화면에서 종료 (12:11) | 정상 |
| 다른 곡 `bethere` 플레이 중 종료 (12:16) — 영상 없음. 곡 선택 프리뷰에서 커스텀 음원 Sound 는 만들어짐 | **정상** |

→ alamode 플레이에만 붙는 **영상** 또는 **플레이 씬에서 재생 중인 커스텀 음원** 이 원인. 다음 대조는 영상만 끄고 alamode 플레이 중 종료.

### 실패한 방법 — `CameraFarPlane`

VideoPlayer 를 `renderMode = CameraFarPlane` 으로 카메라에 붙이면 재생·싱크(-43ms)는 되는데 **화면에 안 보입니다.**
먼 평면은 씬 전체보다 뒤인데, 불투명 배경 메시가 화면을 전부 덮기 때문입니다.
URP 에서는 카메라 평면 영상이 불투명·반투명 오브젝트를 다 그린 뒤(`InvokeOnRenderObjectCallbackPass`)에 깊이 비교로
그려지는 것으로 보이며(추정), 배경이 이미 깊이를 채운 자리는 전부 탈락합니다.

### 새 곡 주입 시험 (`NewSongInjector.cs`, 같은 날 12:23~12:33)

alamode 를 복사해 SongId 71·슬러그 `hwa`·제목 "hwa custom" 으로 넣었습니다. 세이브는 시험 전에

| 회차 | 방식 | 결과 |
|---|---|---|
| 1 | allSongInfo **끝(83번 칸)에 추가** + 팩 `all` 에 추가 | 팩 선택 화면이 곡 항목 `_K._SH..ctor(SongInfo, 난이도, 언어)` 에서 `IndexOutOfRangeException` 2회 → 곡 선택 화면이 프리팹 기본값(`Long Back Title` 등)인 채 멈춤. Player.log 에 `Uploading Crash Report` |

**1회차 원인:** allSongInfo 가 SongId 인덱싱이라 게임은 `allSongInfo[71]` 을 곡으로 가져오는데, 그 칸은 차트 0개짜리 더미였습니다.

**자켓 사전은 곡을 고를 때마다 다시 만들어집니다.** 2회차에 `_Dfb` 가 74→73, `_efb` 가 287→283 으로 곡 선택 이동마다 되돌아갔습니다
(원본 배열 `songIdJacketMaterials` 73·`chartIdJacketMaterials` 283 과 같은 수). 원본 배열에 항목을 붙이면(3회차) 조용해집니다.

**새 곡 전용 자켓 (4회차):** 새 곡에 자켓 항목을 넣지 않으면 게임은 기본 자켓 `nojacket`(256x256, `SongData.FallbackJacket*Material`)을
씁니다(2회차에 확인). JacketInjector 의 대상을 alamode 에서 `nojacket` 으로 바꿔 그 텍스처 내용을 Thumbnail.png 로 교체했습니다.
원곡 자켓은 건드리지 않습니다. **한계:** 이 방식으로는 커스텀 곡 한 곡만 자기 자켓을 가질 수 있습니다.

**새 곡 전용 음원 (4회차):** 에셋 등록부 배열 4개(`_TxA` FileInfo·`_uxA` 길이·`_UxA` 플래그·`_vxA` 복호화 정보 `_DG`)를 한 칸 늘려
`alamode.wav`(5610) 항목을 그대로 복제하고 `hwa.wav` 를 새 칸 **AssetId 10344** 에 걸었습니다. 배열 복사는 `Il2CppSystem.Array.Copy` 한 번으로 합니다.
AudioInjector 는 5610 대신 10344 만 가로채므로 원곡 음원은 그대로이고, 가로채기가 실패해도 hwa 에서 원곡 음원이 나올 뿐입니다.
곡 선택 프리뷰에서 `_NGA(10344)` → music.ogg 교체 확인. 차트 `hwaN.spc` 는 아직 원곡 차트 AssetId 별칭입니다.

**세이브 정리:** hwa 를 고른 채 종료하자 메모리의 `PackIdToSelectedSongId` 에 71 이 들어가 있었고, 종료 정리가 원곡 ID 2 로 되돌렸습니다
(`세이브 정리(게임 종료): 마지막 선택 곡 1개 팩 → SongId 2`). 네 번 모두 세이브 파일은 백업과 같았습니다 — 곡 선택만 해서는 게임이 파일을 쓰지 않습니다.

**아직 남은 것:** 새 곡 플레이(점수 기록 차단 필요 — `TryUpdate` 는 `ref SongInfo` 라 후킹 불가), 새 곡 전용 채보(지금은 원곡 차트 별칭),
커스텀 곡 여러 개(자켓 방식의 한계).
