# 06. 커스텀 채보 — BMS

[← 문서 목록](README.md)

새 곡 **hwa custom**(SongId 71) 의 채보를 **BMS** 로 씁니다. 사용하는 에디터는 3자리 키음을 지원하는 자체 BMS 에디터
(`H:\source\repos\bms editer`, `ibmsc-custom-editer`)이고, 노트 종류는 **WAV 파일 이름**으로 가릅니다(GRC 곡 폴더와 같은 방식).

지금은 **뼈대** 단계입니다 — 정해진 하단 노트만 게임에 들어가고, 스카이는 읽어서 개수만 셉니다.
다음에 정할 것은 [4장](#4-다음-단계--고민할-것).

## 1. 파일 위치

| 난이도 | 파일 |
|---|---|
| MIN (Minimal) | `In Falsus/hwa/hwa0.bms` |
| EVO (Evolved) | `In Falsus/hwa/hwa1.bms` |
| ULT (Ultimate) | `In Falsus/hwa/hwa2.bms` |
| FOR (Forbidden) | `In Falsus/hwa/hwa3.bms` |

`.bme` · `.bml` 도 읽습니다. 파일이 없는 난이도는 원곡 à la mode 채보가 나옵니다(곡 선택에 보이는 난이도는 원곡 설정).
파일을 고치고 곡 선택에서 hwa custom 을 **다시 고르면** 반영됩니다(플레이 중 재시작으로는 다시 읽지 않음).
점수는 세이브에 기록되지 않습니다(`ResultGuard`).

음원은 BMS 의 `#WAV` 가 아니라 `hwa/music.ogg` 를 게임이 재생합니다(`AudioInjector`). BMS 의 BGM 은 **타이밍 기준**으로만 씁니다.

## 2. 지금 되는 것 (뼈대, `BmsChart.cs`)

### 시간 — tick 공식

위치를 마디 단위 tick 으로 잡습니다. 마디 `m` 의 데이터가 `N` 칸이면 `k` 번째 칸은

```
tick = (m 마디 시작 tick) + (m 마디 길이) × k / N
time(초) = Σ Δtick × 240 / bpm            ← BPM 이 바뀌는 자리마다 구간을 나눠 더함
게임 노트 시각(ms) = (time(노트) − time(01 채널 BGM)) × 1000
```

| 채널·헤더 | 처리 |
|---|---|
| `#BPM` | 처음 BPM (없으면 130 + 경고) |
| `03` | BPM 변경 (16진수 2자리 값) |
| `08` + `#BPMxx` / `#BPMxxx` | BPM 변경 (참조) |
| `02` | 마디 길이 (1 = 4/4, 0.75 = 3/4) |
| `01` | BGM — `#WAV` 가 음원(`.ogg` `.mp3` `.flac`, 또는 이름에 `music` 이 든 `.wav`)인 **가장 이른 오브젝트** = 음원 0ms. 없으면 000마디 시작 = 0ms + 경고 |

BPM 변경은 게임 차트처럼 이벤트(종류 1)로도 넣습니다(박자선용).

### 키음 자릿수·인코딩 — 에디터와 같은 규칙

- `#WAV` 에 3자리 키가 하나라도 있으면: 데이터 길이가 3의 배수(2의 배수 아님)면 3자리, 6의 배수면 `#WAV` 표에 더 많이 맞는 쪽.
- 인코딩: BOM → 엄격 UTF-8 → CP949.

### 하단 노트

| 채널 | 레인 |
|:---:|:---|
| `16` | 왼쪽 바깥 |
| `11` `12` `13` `14` | A S D F |

노트 종류는 그 노트가 가리키는 `#WAV` **파일 이름** 키워드로 가립니다(대소문자 무시, 부분 일치):

| 파일 이름에 | 종류 |
|:---|:---|
| `홀드 끝` `홀드끝` `hold end` `holdend` `hold_end` | 홀드 끝 |
| `홀드` `hold` | 홀드 시작 |
| 그 밖 (`#WAV` 에 없는 키 포함) | 단노트 |

홀드 짝: 레인마다 시간순으로, 시작 다음에 오는 끝과 짝. 같은 자리면 끝이 먼저(이어지는 홀드).
끝 없이 시작이 또 오면 앞 시작을 버리고, 짝 없는 끝·끝 없는 시작도 버립니다 — 전부 로그에 경고.

### 아직 안 넣는 것

- `15` `18` (스카이) — 개수만 세고 경고 `스카이 채널(15·18) 노트 N개 — 좌우 위치 규칙이 정해지기 전이라 넣지 않음`
- 그 밖의 채널, `#LNOBJ` · `#LNTYPE` · LN 채널(`5x`), `#RANDOM` 조건 블록 (조건 블록은 모든 갈래를 읽음)

### 확인 방법

MelonLoader 로그(`MelonLoader/Logs/` 최신)에서:

```
[ChartInjector] hwa0.bms — 단노트 120, 홀드 8, 스카이(미반영) 0, BPM 125, BPM 변경 0, BGM 오프셋 0ms, 키 3자리, 인코딩 UTF-8
[ChartInjector]   ⚠ (경고가 있으면 줄마다)
[ChartInjector] 'hwa0.spc' 커스텀 채보 주입 — hwa0.bms: 노트 128개(원곡 132개 대체) …
```

오프라인 검증(게임 없이, 2026-09-24): 합성 BMS 로 BPM 변경(03·08)·마디 길이(02)·3자리 키·BGM 오프셋·홀드 짝이 계산대로 나오는 것,
GRC 커스텀 곡 5개(`GUNVOLT RECORDS Cychronicle/hwa/*/hwa2.bms`)가 예외 없이 읽히는 것을 확인. **인게임 확인은 아직.**

## 4. 다음 단계 — 고민할 것

### ① 스카이 좌우 위치를 어디에 담을까 ★ 가장 큰 문제

스카이는 하단처럼 칸이 없고 **화면 왼쪽 끝(0) ~ 오른쪽 끝(1) 어디에나** 놓입니다. 시간은 BMS 마디 위치로 정해지지만,
좌우 위치는 따로 담을 곳이 필요합니다. 스카이는 **시작 x · 끝 x 두 개**와 **폭**까지 필요합니다.

원곡에서 실제로 쓰인 수 (차트 283개):

| | 종류 수 | 90% 를 덮는 수 |
|:---|---:|---:|
| 플릭 (x · 폭 · 방향) 조합 | 1,683 | 394 |
| 스카이 x 값 | 442 | 45 |
| 스카이 폭 | 187 | 22 |

x 값이 12등분에 딱 맞는 게 66%, 16등분 48%, 48등분 82%.

후보:
- **WAV 이름에 위치까지** — `플릭 왼쪽 3.wav` = 12등분 중 3. 쓰는 위치마다 `#WAV` 가 늘어남
- **채널을 늘려 칸으로** — 스카이용 채널 여러 개(2P 등)를 두고 채널 = 좌우 칸. WAV 는 종류만
- **15 = 왼쪽, 18 = 오른쪽 고정** — 단순하지만 원곡 같은 배치는 못 함
- 스카이 시작/끝처럼 **움직이는** 노트는 시작 x 와 끝 x 가 다름 — 위 방법으로 끝 x 를 어떻게 적을지도 같이

### ② 오른쪽 바깥 레인 채널

원곡 9,980노트(왼쪽 바깥 8,403)로 많이 쓰입니다. 지금은 `16`(왼쪽 바깥)만 있고 오른쪽 자리가 없습니다. 후보: `19`, 또는 스카이 채널 정리와 같이.

### ③ WAV 이름 최종 목록

지금 모드가 아는 키워드는 홀드 시작/끝뿐입니다(나머지는 단노트). 스카이까지 정해지면 이름을 확정합니다:

| 노트 | 이름 예 |
|:---|:---|
| 단노트 | `단노트.wav` |
| 홀드 시작 / 끝 | `홀드.wav` / `홀드 끝.wav` |
| 플릭 두 방향 | `플릭 왼쪽.wav` / `플릭 오른쪽.wav` |
| 스카이 시작 / 끝 | `스카이.wav` / `스카이 끝.wav` |
| 스카이 곡선 | 시작을 `스카이 00.wav` ~ `스카이 22.wav` 로 나눌지 |

곡선 없이 7개, 곡선까지 15개 + 음원.

### ④ 인게임으로 확인할 것

- **플릭 방향** — 게임 값 1024 / 4096 중 어느 쪽이 왼쪽인지. 원곡에서 1024 는 화면 오른쪽, 4096 은 왼쪽에 더 많음(추정만 함)
- **곡선 9가지 모양** — 게임 값 `(4<<a)|(32<<b)`, a·b ∈ 0~2. 원곡 빈도 `00` 43% · `11` 29% · `22` 20%
- **결과 화면 점수 차단** — `ResultGuard` 가 결과 화면에서 기록을 막는지 (아직 결과 화면까지 가 본 적 없음)
- **BMS 첫 인게임 테스트** — 하단 단노트·홀드, BGM 오프셋, 파일 고치고 다시 고르면 반영되는지

### ⑤ 쓸지 정할 것

- **넓은 노트** — 단노트·홀드가 2~4칸 폭으로 나오는 것(원곡 하단의 약 9%). 쓴다면 표현 방법
- **레인 닫기/열기** — 4키 ↔ 3키 기믹(원곡 1,574번). 쓴다면 채널이나 WAV 하나
- **스크롤 속도 변경** — 원곡 1,705번. `#SCROLL` 같은 확장을 받을지

### ⑥ 곡 폴더·곡 정보

GRC 처럼 `hwa/<곡>/` 폴더에 `hwa0.bms`·`music.ogg`·`Thumbnail.png`·`video.mp4`·`info.txt` 를 두는 구조로 가면
곡 여러 개를 넣을 수 있습니다. 지금은 `hwa/` 바로 아래 한 곡(음원·자켓·영상)뿐입니다.
`#TITLE` · `#ARTIST` · `#PLAYLEVEL` 은 읽어 두기만 하고 아직 게임에 안 씁니다(제목은 "hwa custom" 고정).

### ⑦ 에디터 쪽

`bms editer` 에 `infalsus` 게임 프로파일(`Profiles/infalsus.json` + `docs/guides/in_falsus.md` + 게임 표 한 줄)을 추가하면
홀드 짝·스카이 짝이 격자에 보입니다. 채널·WAV 이름이 확정된 뒤에.
